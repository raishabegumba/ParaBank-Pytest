7. FUNCTIONAL REQUIREMENTS SPECIFICATION (FRS)
MODULE 1 — USER REGISTRATION
7.1 Feature Overview
Attribute	Value
Module ID	MOD-001
Module Name	User Registration
Primary Actor	Anonymous User
Goal	Create customer banking profile
Priority	High
________________________________________
7.2 Functional Requirements
FR-REG-001 — User Registration
The system shall allow a new user to create a customer account.
FR-REG-002 — Mandatory Field Validation
The system shall validate all mandatory registration fields before submission.
FR-REG-003 — Username Uniqueness
The system shall reject duplicate usernames.
FR-REG-004 — Password Confirmation
The system shall validate that password and confirm password fields match.
FR-REG-005 — Persistent User Creation
The system shall persist successfully registered users.
FR-REG-006 — Post-Registration Authentication
The system shall redirect the user to the authenticated account area after successful registration.
________________________________________
7.3 Registration Fields
Field	Type	Mandatory	Validation
First Name	String	Yes	Non-empty
Last Name	String	Yes	Non-empty
Address	String	Yes	Non-empty
City	String	Yes	Non-empty
State	String	Yes	Non-empty
ZIP Code	Numeric/String	Yes	Valid ZIP format
Phone	Numeric/String	No	Valid phone format
SSN	String	Yes	Valid pattern
Username	String	Yes	Unique
Password	Password	Yes	Match confirmation
Confirm Password	Password	Yes	Match password
________________________________________
7.4 Acceptance Criteria
AC-REG-001
Given a user enters valid registration details
When the user submits the registration form
Then the system shall create the account successfully.
AC-REG-002
Given a duplicate username exists
When the user submits registration
Then the system shall display a validation error.
AC-REG-003
Given mandatory fields are blank
When the user submits the form
Then validation errors shall be displayed.
AC-REG-004
Given password fields do not match
When the user submits the form
Then the system shall reject the registration.
AC-REG-005
Given registration succeeds
When account creation completes
Then the user shall be redirected to the account overview page.
________________________________________
7.5 Security Requirements
Requirement ID	Requirement
SEC-REG-001	Password fields shall be masked
SEC-REG-002	Input validation shall prevent malformed input
SEC-REG-003	Authentication pages shall use HTTPS
________________________________________
7.6 Non-Functional Requirements
NFR ID	Requirement
NFR-REG-001	Registration response time shall be below 3 seconds
NFR-REG-002	Registration shall support keyboard navigation
NFR-REG-003	Validation messages shall be human readable

8.1 Feature Overview
Attribute	Value
Module ID	MOD-002
Module Name	Authentication
Primary Actor	Customer
Priority	Critical
________________________________________
8.2 Functional Requirements
FR-AUTH-001
The system shall authenticate valid users.
FR-AUTH-002
The system shall reject invalid credentials.
FR-AUTH-003
The system shall create an authenticated user session after successful login.
FR-AUTH-004
The system shall terminate the session during logout.
FR-AUTH-005
The system shall restrict access to authenticated pages for unauthenticated users.
________________________________________
8.3 Acceptance Criteria
AC-AUTH-001
Given valid credentials
When the user logs in
Then the system shall redirect the user to the accounts overview page.
AC-AUTH-002
Given invalid credentials
When login is attempted
Then the system shall display an authentication error.
AC-AUTH-003
Given an authenticated user
When the user logs out
Then the authenticated session shall terminate.
AC-AUTH-004
Given an unauthenticated user
When the user accesses a protected page
Then the system shall deny access or redirect to login.
________________________________________
8.4 Security Requirements
Requirement ID	Requirement
SEC-AUTH-001	Authentication pages shall require HTTPS
SEC-AUTH-002	Sessions shall be invalidated during logout
SEC-AUTH-003	Passwords shall never be displayed in plaintext
